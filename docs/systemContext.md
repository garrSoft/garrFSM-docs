## Current System State (Infrastructure & Networking)

### Domains & Cloudflare
- Cloudflare is authoritative DNS for the project domain
- A Cloudflare Tunnel is the only external entry point
- No inbound ports are exposed on the server
- Public hostnames are intentionally omitted from this document

Traffic model:
- Internet → Cloudflare → Tunnel → local service

### Backend (Docker)

#### Production stack
- Postgres (prod)
  - Containerized
  - Bound to localhost only
- API service (prod)
  - Containerized
  - Bound to localhost only
  - Accessible exclusively via Cloudflare Tunnel

#### Dev / demo stack (fully separated)
- Postgres (dev/demo)
  - Containerized
  - Bound to localhost only
- API service (dev/demo)
  - Containerized
  - Bound to localhost only
  - Accessible exclusively via Cloudflare Tunnel

### Frontend – Admin

#### Production (live)
- Built with Vite → static files
- Served by Nginx on the host
- Bound to localhost only
- Accessible exclusively via Cloudflare Tunnel
- Public hostnames are intentionally omitted

Deploy process
- `cd ~/dev/garrFSM/apps/admin`
- `npm run build`

#### Development (current workflow)
- Vite dev server runs on the dev server, bound to 127.0.0.1 only.
- API and Postgres stacks are containerized and also bound to localhost.
- No LAN or public exposure.

Access model:
- From Mac, SSH port forwarding is used:
  - 5173 → dev server 127.0.0.1:5173 (Vite Admin UI)
  - 4000 → dev server 127.0.0.1:4000 (prod API) or 4001 (dev API)
- Admin UI connects to the API via:
  - VITE_API_BASE_URL
  - VITE_API_KEY

Operational note:
- Vite reads environment variables at startup.
- Restart Vite after changing .env.local or .env.development.local.

#### Security posture
- All public traffic flows: Internet → Cloudflare → Tunnel → local service
- Prod and dev are fully separated:
  - APIs
  - databases
  - volumes
  - API keys

## AI Interaction Preferences (Important)

### Working style
- Work **one step at a time**
- Always define a **checkpoint**
- Do not jump ahead
- Prefer clarity over cleverness
- Minimize repeated context requests

### Tooling & workflow constraints
- Primary editor: **VS Code Remote SSH**
  - Do not assume use of interactive terminal editors (`nano`, `vim`) unless explicitly requested
- Prefer **non-interactive** commands and scripts

#### Installed / available
- `docker`
- `node`, `npm`, `npx`
- `git`
- `curl`
- `rsync`
- `make`
- `jq`

#### Not installed (do not suggest without installing first)
- `rg` (ripgrep) — use `grep -RIn`
- `psql` — use `./tools/bin/db.sh ...`
- `docker-compose` — do not assume legacy binary
